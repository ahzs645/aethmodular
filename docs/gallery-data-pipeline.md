# Gallery data pipeline

How the gallery's newer data is rebuilt: AERONET, the **Instruments → Aethalometer** pages,
the **Research diagnostics** pages, the Data availability AERONET view and the MAIA catalogue.
It also covers how private sections are kept out of the public gallery.

One script runs it, in order and checking inputs first: `gallery/data/rebuild.py`, run as
`aeth gallery …`. This page explains it. The step table below is generated from the script,
and `tests/test_gallery_rebuild.py` fails if the two drift apart.

Older exporters (meetings, baselines, similarity, calibration) keep their own instructions in
[gallery/README.md](../gallery/README.md).

## The short version

```bash
uv sync --python 3.13 && (cd gallery/app && npm ci)    # environments
uv run aeth doctor                                      # data paths resolve?
uv run aeth gallery plan                                # every step, and what it is missing
uv run aeth gallery rebuild                             # run every step whose inputs are present
uv run aeth gallery check                               # chart index, typecheck, tests, public-build check, sizes
git status gallery/app/public/data                      # review what changed, then commit
```

- `rebuild --fetch` also runs the network steps: the AERONET pulls and the MAIA catalogue.
- `--only STEP…`, `--from STEP` and `--skip STEP…` narrow a run. `--dry-run` shows what would run.
- A step whose inputs are missing is **skipped**, and its committed output is left alone. A step
  after a failed one is skipped.
- Every run writes `research/ftir_hips_chem/output/tables/gallery_rebuild/last_run.json`
  (gitignored): what ran, how long it took, which data roots resolved, and the commit.

## 1. Inputs and where they live

| Input | Where | Needed by |
|---|---|---|
| Filter windows (local start/end per filter) | `gallery/app/public/data/weather/filters.json` (committed; made by `weather`) | every per-filter export |
| MA350 daily aggregates | `research/ftir_hips_chem/processed_sites/*.pkl` (committed) | `aethalometer`, `aeth-filters`, `aeth-quality`, `aeth-sources` |

| "Davis Data" Drive folder | Google Drive, or a local mirror (below) | minute/hourly MA350, IMPROVE exports, FTIR spectra and tables |

### The Drive, or a mirror of it

On a Mac signed in to the research Drive, the resolvers in
`research/ftir_hips_chem/scripts/data_paths.py` find the folder on their own. Anywhere else (a
cloud container, CI), mirror it:

```bash
# .env (gitignored): the folder id from the share link. Never commit the link.
DAVIS_DRIVE_FOLDER_ID=<id>
uv run aeth drive mirror --dest /path/to/davis_data --link-root /path/to/drive_root
```

The mirror script prints the `.env` lines to add:

```bash
AETHMODULAR_MAIA_DATA_ROOT=/path/to/davis_data
AETHMODULAR_FTIR_SPECTRA_DIR=/path/to/davis_data/FTIR
AETHMODULAR_FTIR_LOCAL_DB=/path/to/davis_data/FTIR/local_db
AETHMODULAR_DRIVE_ROOT=/path/to/drive_root
```

`AETHMODULAR_DRIVE_ROOT` is needed because `pls_transfer.FTIRTransferPaths` reads only that
variable, and expects `University/Research/Grad/Data/Davis Data` beneath it. `--link-root`
creates that path as a symlink.

What the mirror takes:

- **All working files, about 17 GB.** It leaves out the `_archive/` zips, the mirrored Shiny app,
  the `*uncleaned*` duplicate pickles and the PNGs. Flags take those too.
- **Resumable.** It stops taking new files below `--min-free-gb`.
- **A manifest.** It writes `MIRROR_MANIFEST.json` in the mirror.
- **Data only.** The mirror holds the lab's `.py`, `.R` and `.ps1` files. Read them; never run
  them from inside the mirror.

The Drive files the exporters read, relative to the root:

- **`Aethalometry Data/Raw/`**: `Jacros_MA350_1-min_2022-2024_Cleaned.csv` (Addis) and
  `Pasadena_MA350_1-min_2023-2024_Cleaned.csv`. These are raw 1-minute MA350 files.
- **`Aethalometry Data/Kyan Data/MAIA data/`**: `{Beijing,Delhi,JPL,Central}_cleaned_corrected_small_hourly.csv`,
  hourly means. "Central" is an unidentified Addis instrument and is not used.
- **`Improve/`**: `IMPROVE_chem-mass-fabs_2026-04-22.xlsx` and `IMPROVE_laser-optics-635nm_2026-04-22.xlsx`.
  See the data-use condition in section 5.
- **`FTIR/local_db/`**: the offline IMPROVE mirror, with `improve_local.sqlite` and `tables/results_*.csv`.
- **`DAVIS/ETAD FTIR/`** and **`DAVIS/SPARTAN FTIR pulls/`**: spectra and metadata.
- **`Spartan/SPARTAN_HIPS_Batch1-51.v2.csv`** and **`DAVIS/SPARTAN HIPS pulls/`**: HIPS batches and raw optics.

## 3. What the data folders hold, and the public flag

`gallery/app/src/sections/sections.json` marks each **section** public, unlisted or private.
Instruments is unlisted and Research is private:

| Section | Tab | Data folder | Size (27 Oct 2026) |
|---|---|---|---|
| `instruments` (unlisted) | Aethalometer (Overview, Against the filters, Sources, Data quality, Diurnal) | `public/data/aethalometer/` | 9.4 MB (2.7 MB gzipped) |
| `research` (private) | Research diagnostics (18 pages) | `public/data/research/` | 0.5 MB (0.1 MB gzipped) |

AERONET (`public/data/aeronet/`, 5.9 MB) is public.

A build with `VITE_PUBLIC_BUILD=1` swaps each private section's module for
`src/sections/omitted.ts` (see `vite.config.ts`), so none of its code is compiled. These builds
set it:

- the GitHub Pages deploy (`gallery/share/pages-deploy.yml`)
- `gallery/share/build_share.py`
- `publish_pages.py --branch`

The publish scripts also leave the section's data folders out of the archive
(`gallery/share/sections.py`), and `build_share.py` refuses a private tab. A local
`npm run dev` or `npm run build` includes everything.

`"public": "unlisted"` works like the Experimental tab. A public build compiles the section and
publishes its data, but the header menu and the search leave its tabs out. They open from a link
(`#tab=aethalometer`, `&aep=<page>` for a sub-page), and the menu shows the section's group while
one is open. Its per-filter fields (the aethalometer's BCc and AAE columns) join the other tabs'
field pickers only in a full build. Unlisted is not private: the data is in the public release.

`aeth gallery check-public` proves it on the current tree. It builds with the flag, checks that
none of a private section's data paths are in the bundle (and that every unlisted section's are),
and checks that the publish packer's archive carries none of a private section's files. To publish
a section, set `"public": true` or `"unlisted"` and run the check.

`aeth gallery sizes` prints data per folder, with and without the private sections. On
27 Oct 2026 in a fresh clone that was 41.2 MB in all and 31.4 MB public. The private sections
add about 0.45 MB of JavaScript. On a machine with the gitignored exports (SPARTAN network,
similarity, baselines, IMPROVE samples), the total is about 126 MB more.

## 4. Publishing checklist

1. `uv run aeth gallery rebuild`, then `uv run aeth gallery check`. The node tests fail 7 times
   in a clone without the gitignored baseline/VIBES/similarity exports; any other failure is real.
2. Review `git diff --stat gallery/app/public/data`. A step that changed nothing should show no
   diff: the exporters are deterministic apart from `generated` timestamps.
3. Commit and push the gallery source (`publish_pages.py` refuses uncommitted `gallery/app` changes).
4. `python3 gallery/share/publish_pages.py --dry-run`, then without `--dry-run`.

## 5. Rules that keep the numbers right

These were each established by checking the data. Keep them when changing an exporter.

- **One set of filter windows.** Every per-filter value (weather, AERONET, aethalometer) is a mean
  over the filter's own sampling window, taken from `weather/filters.json`. Older intermittent
  filters spread 24 h of sampling over about 8 days, and their window is the elapsed period. The
  notebooks' ±1-day averages are not used.
- **The MA350 daily pickles' bins are labelled at their start.** Beijing, Delhi and JPL bins start
  at 15:00; Addis at 09:00 (`docs/matched-sample-audit-2026-09-10.md`). Read that way,
  r(IR BCc, HIPS Fabs) is 0.86–0.93 at all four sites. Shifted a day it falls to 0.45–0.60.
  Filters take the overlap-weighted mean of the bins, kept where they cover at least 12 h.
- **Jacros is the Addis instrument.** `df_Jacros_9am_resampled.pkl` is the same MA350-0238 as the
  Addis file, and BCc is identical on all 515 shared bins. It is the longer record, not a second
  instrument.
- **In the raw MA350 CSVs, "Time local" is UTC.** `Timezone offset (mins)` is 0 on every row, and
  the column equals `Time (UTC)`. Always take `Time (UTC)` and convert to the site's zone
  (Africa/Addis_Ababa, America/Los_Angeles). The August diurnal-coverage check got this wrong; see
  the correction in `research/ftir_ec_phase3/AERONET_SPARTAN_2026-08-22.md`.
- **AAE comes from absorption, not BCc.** Absorption is BCc × the MA350 cross-section
  (`research/ftir_hips_chem/scripts/optics.py`). An AAE from BCc is about 1.0 lower, which puts
  Addis at 20 % biomass instead of about 52 %.
- **The pickles' "smoothed" BCc is the cleaning pipeline's 10-minute DEMA per tape spot**
  (`src/data/qc/pkl_cleaning.py`), not the instrument's smoothing.
- **Known bad channels at Addis.** UV is negative on 145 of 515 days, and Green reads about half
  the other channels. The pages flag both.
- **AERONET Level 1.5** is cloud-screened but not final-calibrated. Absorption (AAOD, SSA, AAE) is
  uncertain where AOD 440 < 0.4, so the timeline draws those days hollow. Level 2.0 drops most
  absorption retrievals: Addis has 9 of 169 filters, Pasadena 0 of 213.
- **AERONET retrieves only in daylight and clear sky.** At Addis the inversions fall at 07–10 and
  14–17 local. The 24 h ÷ AERONET-hours ratio is 0.88 at Addis and about 0.98 at Pasadena.
- **IMPROVE data-use condition.** The Overview sheet of the FED exports asks that Anthony Prenni
  (NPS) be notified of any planned journal publication. Results derived from them
  (`research/improve_envelope`, `research/improve_origin`) stay in the private Research section.
- **The MAIA catalogue** (`aeth maia catalog`) is public metadata. Downloading granules needs
  `EARTHDATA_TOKEN`.

## 6. Adding a step or a section

- **A new exporter.**
  1. Write it under `gallery/data/`, with a docstring naming its inputs, outputs and run command.
  2. Add a `Step` to `STEPS` in `gallery/data/rebuild.py`: its key, inputs (`needs`) and the
     steps it must follow (`after`).
  3. Regenerate the table above with `uv run aeth gallery markdown`, and paste it between the
     markers.
  4. `tests/test_gallery_rebuild.py` checks the order, that every script exists, and that this
     page matches.
- **Private data** goes under a private section's data folder. Anything below
  `public/data/<folder>/` is covered by the flag once the folder is listed in `sections.json`.
- **A new private section.**
  1. Add it to `sections.json`.
  2. Add `src/sections/<key>/index.tsx`, exporting a `Section` (`src/sections/types.ts`).
  3. Import it in `App.tsx`'s `SECTIONS`.
  4. Run `aeth gallery check-public`.

## 7. Troubleshooting

- **A cloud container's disk is a fixed allowance.** The Drive mirror is 17 GB and the AERONET
  cache 1 GB. If space runs out, delete scratch copies before data the pipeline reads.
- **Memory.** Read the minute CSVs in chunks, with `usecols`. The 1.5–4 GB pickles in
  `Aethalometry Data/Kyan Data/Dataset/` and `JacrosMA350 60s Data…/` need several times their
  size in RAM, and no step reads them.
- **`timezonefinder`** is not in the lock. Steps that need it run with
  `uv run --with timezonefinder`, which `rebuild.py` does for you.
- **The gallery shows 0 filters in a fresh clone.** The default SPARTAN-network view needs the
  gitignored `spartan_network/` export. Check pages with `&net=focus`.
