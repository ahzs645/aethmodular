# Calibration Explorer audit — 2026-08-24

## Outcome

The core workflows are coherent and usable: calibration, k sweeps, target
readout, cohort diagnostics, analog metrics, dated series, five-site readout,
HIPS/York diagnostics, pinned comparisons, and server-side grid search all ran
successfully. The audit found and fixed several release-level integrity gaps.

## Fixed in this pass

### Reproducible startup and Colab recreation

- Added the optional `explorer` dependency set and locked it. The IKPLS marker
  now preserves Python 3.9 resolution while the documented Python 3.13 path gets
  the accelerator.
- Updated the documented clean-start command.
- Added `hips_lab.py`, `target_registry.json`, all shipped target assets, and the
  complete runtime layer to the Colab bundle builder.
- Rebuilt the Colab notebook and prewarm archive.

### Cache and run provenance

- Curve/fit cache keys now include a cache-schema and a content fingerprint of
  the loaded training arrays, cohort orderings, corrected spectra, and shared
  calibration code.
- Fit keys also include the target-content fingerprint.
- Cache writes are atomic.
- Every run carries a stable run id, source/target/cohort fingerprints, cache
  schema, git commit, and dirty-worktree flag.
- Pins now preserve exact model configuration, target/evaluation lot, readout
  toggles, extrapolation, metrics, timestamp, and provenance. They can be loaded
  and rerun, and exported as JSON manifests or expanded CSV.

### Target-role integrity

- Added an explicit target registry.
- The five primary targets are available for screening.
- Reconstructed holdouts and augmented targets are marked provisional and are
  blocked from browser optimization, exhaustive batch search, and cutoff
  refinement.
- Cross-site and HIPS defaults operate on the five primary physical sites rather
  than treating every target variant as a separate site.

### HIPS scientific correction

- Blank refits now group by `(LotId, deployed Intercept, deployed Slope)`.
  The batch contains four lots but nine distinct deployed calibration lines;
  lots 248, 250, and 251 each contain multiple lines.
- The UI no longer states that intercept stability proves an aerosol cause.
  Stability only rules out the tested blank-line forms.
- The revised view renders five site rows and nine calibration-line ledger rows.

### UI and large-grid behavior

- Changing configuration marks the displayed result stale and disables Pin/Sweep
  until a matching run completes.
- Locked/provisional targets visibly disable optimization.
- Network/non-JSON failures and invalid small cohorts now yield actionable errors.
- Saved results are filtered server-side and capped at 10,000 rows per request.
  Frontend deduplication is O(n) and the UI reports matched/total/truncated counts.
- Generic target wording replaces misleading Addis-only readout labels.
- Busy/error messages gained live-region semantics.

## Verification

- Clean environment: `uv run --extra explorer` resolves and launches.
- Startup membership checks: 300/300, 500/500, and 800/800.
- API smoke: `/api/run`, `/api/cross_site`, `/api/hips_york`, target-role
  rejection, filtered `/api/batch_results`, and `/api/hips_blanks` all behaved as
  expected.
- Browser smoke: valid run enables Pin/Sweep; configuration change displays the
  stale warning and disables them; locked target disables Optimize; 10,000 of
  71,263 saved rows loaded in about 2.8 seconds; HIPS rendered 5 site and 9 line
  rows; no console warnings/errors.
- Full repository pytest suite passed.
- Ruff, Python compilation, JavaScript syntax, and `git diff --check` passed.
