# Calibration Explorer on Colab: launcher, bundle, and what we learned

The Colab path runs the same Flask explorer on a Colab VM, reading the 4.6 GB FTIR
source tree from the user's mounted Drive and everything else from a prewarmed
zip. Two artifacts, both generated by `build_colab_bundle.py` (edit the template
there, never the `.ipynb` directly):

| Artifact | What it is |
|---|---|
| `Calibration_Explorer_Colab.ipynb` | 19-cell launcher: mount Drive, unpack, pip layer, validate Drive paths, start Flask, open via Colab port proxy, optional batch grid |
| `aethmodular_calibration_explorer_prewarm.zip` | ~297 MB: app + `hips_lab.py` + `local_lab.py` + targets + AIRSpec/neutral caches + cohort tables + shared scripts + `unified_filter_dataset.pkl` + PMF CSV; `PREWARM_MANIFEST.json` records build time, commit, and `git_dirty` |

## Build and ship

```bash
python calibration_explorer/colab/build_colab_bundle.py
cp calibration_explorer/colab/aethmodular_calibration_explorer_prewarm.zip \
   "$HOME/Library/CloudStorage/GoogleDrive-<account>/My Drive/Aethmodular Colab/"
cp calibration_explorer/colab/Calibration_Explorer_Colab.ipynb \
   "$HOME/Library/CloudStorage/GoogleDrive-<account>/My Drive/Aethmodular Colab/"
```

The notebook looks for the zip at `/content/drive/MyDrive/Aethmodular Colab/` and
falls back to an `rglob` of My Drive. Commit before building if the bundle will
leave your machine: the manifest pins the commit and flags `git_dirty`.

**Verify the upload cloud-side before starting Colab.** The macOS Drive client
can silently stall on new files (2026-09-01: a 297 MB zip synced in minutes while
an 8 KB `.py` copied next to it never appeared in ~15 min). A local `ls` proves
nothing; search for the file in the Drive web UI and check its modified time.

## Verification log

### 2026-09-01: first end-to-end run since the Aug 23/24 modules landed

Driven through the notebook cell by cell. Outcome: explorer boots on Colab
(~10 s after unpack), every cohort-identity startup check passes (Ethiopia-shaped
300/300, analog 500/500, lowest-OC/EC 800/800), and `POST /api/run` on `etbi`
with the locked winner (`ocec` 440, AIRSpec, k=8, site-held-out) returns
n = 26, held-out TOR R² = 0.924: identical to the local server. The Colab
deployment is scientifically equivalent to the machine it was built on.

Three bugs found by this run, all fixed the same day:

1. **`ModuleNotFoundError: hips_lab`** at `app.py` import. The bare
   `import hips_lab` / `import local_lab` only resolve when `app.py` runs as a
   script from its own directory; the launcher does
   `importlib.import_module("calibration_explorer.app")`, where
   `calibration_explorer/` is not on `sys.path`. Fix: `app.py` now falls back to
   `from calibration_explorer import hips_lab` (same for `local_lab`), and the
   launcher's cell 4 also inserts `WORK_ROOT / "calibration_explorer"` on
   `sys.path`. Either alone is sufficient; both are in.
2. **`local_lab.py` missing from the bundle.** Added to `build_bundle()`'s file
   list. It had been required at import time since 2026-08-24.
3. **`ETAD Factor Contributions .csv` (PMF) missing from the bundle.** Benign
   (startup warning; season scheme unaffected) but the PMF grouping feature was
   dark on Colab. Added.

Rule this implies: **any new module that `app.py` imports at module level must
be added to `build_bundle()`**, and the launch path should be re-run after
adding one. The startup-check block in the launch cell is the place to look; a
⚠ line there is a bundle gap until proven otherwise.

Also observed:

- `output.serve_kernel_port_as_window` prints a deprecation warning
  ("may stop working due to changes in browser security"). It still works; the
  template should move to `serve_kernel_port_as_iframe` when convenient.
- Drive mount can time out (`ValueError: mount failed`) if the permission dialog
  is not answered within ~2 min. Re-running the mount cell is enough; once
  granted, the session does not prompt again.
- On the day, the Drive bundle was two weeks stale (Aug 18, 101 MB, Addis-only)
  even though the repo had four more targets and the HIPS/LOCAL tabs. The
  manifest's `built_at_utc` is the quick way to tell what a Colab session is
  actually running.
- Workaround when a small file will not sync: base64 it into a single-line
  notebook cell (`open(p, "wb").write(base64.b64decode("..."))`) and check the
  sha256 against the local file. A single line avoids Colab's auto-indent
  mangling multi-line pastes.
